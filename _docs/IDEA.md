## `codexignore`（検索専用 ignore）を設定で指定できるようにする

### 背景

現在の `@` ファイル検索は `.gitignore` 等の ignore ルールを尊重するため、例えば `/_local/` や `/_release/` のような「git には入れないが、作業上は検索したい」領域が検索から外れてしまうことがある。

一方で、検索の“ノイズ削減”や“秘密ファイルの誤表示回避”の観点から、デフォルトで `.gitignore` を尊重する設計自体には合理性がある。

### ねらい

- `.gitignore`（VCS 用）と「Codex の検索対象制御」を分離したい
- リポジトリ/プロジェクトごとに「検索だけ除外したいパス」を追加できるようにしたい
- 逆に「gitignore で隠れているが検索はしたい」ケースも、設定で意図を明示できるようにしたい

### 方向性（案）

- `codexignore` のような **検索専用 ignore ファイル**を用意する（名称は要検討）
- そのファイルパスを設定から指定できるようにする
  - `cwd`（起動ディレクトリ）からの相対パス指定を許可したい
  - 可能なら絶対パスも許可
  - 未指定時は無効（現状維持）

### 設計メモ（案）

- 優先順位: `codexignore`（検索専用）→ `.gitignore` → その他（グローバル ignore 等）みたいな合成をどうするか要検討
- 仕様としては `gitignore` 互換のパターン（`ignore` crate の overrides など）に寄せると実装/学習コストが低い
- UI 側では「検索結果が少ない/ゼロ」のときに *“ignore により除外されている可能性”* を示せると、原因特定が早い

## `notify` のペイロード受け渡し方式（arg / stdin / file）

### 背景

現在の `notify` は、通知 JSON を **コマンドライン引数（argv の最後の 1 引数）**として渡している。

- 実装: `codex-rs/core/src/user_notification.rs`
- 課題: Windows は CreateProcess のコマンドライン長上限（約 32,767 文字）に到達しやすく、長いソースコードが `input-messages` / `last-assistant-message` に入ると `notify` の spawn 自体が失敗し得る。

### 方向性

設定で `notify` の JSON 受け渡し方法を選べるようにする。

- `arg`（現状互換・既定）
  - 互換性: 既存の `notify = ["..."]` がそのまま動く
  - 欠点: OS の argv 長制限に弱い（特に Windows）
- `stdin`
  - 互換性: 受け取り側の実装変更が必要（stdin から読む）
  - 利点: argv 長制限を回避できる
- `file`
  - 互換性: 受け取り側は「ファイルパス」を読むだけ（stdin より扱いやすい場合あり）
  - 利点: argv は短く保てる、`stdin` の取り回しが不要
  - 注意: 一時ファイルの置き場所、権限、クリーンアップ、内容の機微（平文）に配慮

### 設計メモ

- 互換性維持のため既定は `arg`。
- Windows 対策としては `file` が最も無難（argv を短くでき、シェルラップも簡単）。
- `stdin` / `file` 選択時も、現行の「通知コマンドは argv の配列で指定」という設計は維持する。
- 追加で「ペイロードの最大サイズ」や「ペイロードに含める項目の縮約（要約/省略）」も検討余地あり。

## TUI composer の送信キーを `Ctrl+Tab` に寄せる

### 背景

現在の TUI composer は `Tab` を送信/queue に使っている。

- 実行中タスクがないとき: `Tab` で即送信
- 実行中タスクがあるとき: `Tab` で queue

この挙動は補完キーとしての期待と衝突しやすく、誤送信の原因になりやすい。

### ねらい

- 無修飾 `Tab` を送信から外して、補完やフォーカス移動の期待を壊しにくくする
- 送信/queue の明示的なショートカットとして `Ctrl+Tab` を検討する
- 既存の `Ctrl+Enter` / `Ctrl+J` 送信との役割分担を整理する

### 方向性（案）

- composer 本文では無修飾 `Tab` を送信に使わない
- `Ctrl+Tab` で「送信、またはタスク実行中なら queue」を行う
- slash command 補完や popup 操作での `Tab` の既存用途は維持する

### 設計メモ（案）

- 端末や入力バックエンドによっては `Ctrl+Tab` を区別して受け取れない可能性がある
- `Ctrl+Tab` を primary にするなら、区別できない環境向けの代替キーも必要
- フッター表示、ツールチップ、`docs/tui-chat-composer.md`、関連テスト/スナップショットの更新が必要
